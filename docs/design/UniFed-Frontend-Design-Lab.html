UniFed Nigeria — Frontend Design Brief Response

From Mastodon structure to a federated academic OS

A design system response grounded in the actual UniFed frontend (Next.js Pages Router, tokens.ts = institutional navy + saffron, DM Sans), not the Mastodon screenshots (used only for information architecture). All component specs below are rendered live so you can confirm the "why" before implementation.

Information Architecture

The brief assumed /campus /assignments /research /admin as primary tabs, but the real tokens.nav ships five tabs: Home · Connect · Create · Discover · Profile. Resolution: keep the 5-tab bar for thumb-reach (Mastodon pattern, endorsed by the brief), and route the academic surfaces through it + a permission-gated slide-out drawer. This matches the existing code rather than fighting it.

Color & Typography System

Base — actual tokens

navy-500 #1E3A5F navy-950 #070c1f saffron #f97316 brand #2563EB

Institutional, warm, low-glare dark — deliberately NOT the monochrome violet of the Mastodon reference.

Content-type accents

Assignment Research Announcement Discussion Admin Event Career

Color signals content type so a scrolling feed is scannable without reading every line.

Role + federation

Student Lecturer Dept Admin Sys Admin
ADUN UniAbuja UNN OAU

Per-institution crest color = instant federation legibility.

Typography

Display / UI : DM Sans (already in tokens) — used for headings, nav, KPIs, buttons.
Body / content : DM Sans 14–15px, line-height 1.5.
Editorial accent : Newsreader (serif) for research abstracts, announcement leads, empty-state copy.
Numeric : DM Sans tabular for KPIs, due-dates, distances.

Serif is used sparingly to give academic "weight" to long-form content — not as a decoration.

Rationale — deviations from the Mastodon reference

1 · Warm institutional palette, not violet-on-black. The Mastodon reference is monochrome purple; UniFed already has navy + saffron tokens. We extend with content-type and role/institution accents so color encodes meaning (hierarchy + scan-ability), not just brand. This directly answers the brief's "everything competes for the same weight."
2 · Per-type card templates. Mastodon renders every post as one generic text card. We give Assignments / Research / Announcements / Discussions / Admin distinct icon + accent + layout, so a feed is legible at a glance. This is the brief's central "don't repeat the boring" point.
3 · Federation crest on every item. The Mastodon UI hides instance origin behind a small handle. Because federation is UniFed's premise, every post/profile/notification carries a color-coded institution chip (ADUN/UNN/OAU…). Cross-campus content becomes instantly legible.
4 · Role-aware identity. Student / Lecturer / Dept-Admin / Sys-Admin get distinct badge colors in profile cards, post authorship, and notifications — a concept absent from the reference.
5 · Drawer bears the academic IA; 5-tab bar stays for thumbs. Rather than cramming /campus /assignments /research /admin into 5 tabs (impossible), we keep the mandated 5 tabs and route academics through a grouped, permission-gated drawer — the exact Mastodon pattern the brief endorsed.
6 · Live-bound profile card. We specify the data contract (useQuery(['profile'])) explicitly so no future card regresses to hardcoded placeholders — addressing the brief's stated risk at the spec level.
7 · Session toast tied to the real gap. The reference has no session state. UniFed's auth.ts stores a refresh token but never calls it; we design the non-intrusive affordance AND flag the backend fix needed (§Corrections).
8 · Serif for academic long-form. Newsreader is used only for research abstracts / announcement leads / empty-state copy — a deliberate "this is scholarship" cue, not decoration.

Source-verified corrections to the brief's "known issues"

Issue A — "Profile cards aren't rendering live data." NOT REPRODUCED frontend/src/pages/profile.tsx binds via useQuery(['profile']) → unifedApi.profile(token) and renders display_name, email, actor_type, bio, skills, university. The card is already live. We keep the contract explicit in §3.3 to prevent future regressions, but no fix is needed.
Issue B — "Admin nav not permission-gated in UI." ALREADY ENFORCED The Admin link renders only when actor_type === "admin" (profile.tsx:117), and admin.tsx is wrapped in RequireAuth + server-side admin:users. Both CSS-hide AND route-guard are present. Recommended: keep both layers (defense in depth).
Issue C — "Token auto-refresh gap." CONFIRMED REAL frontend/src/lib/auth.ts stores refresh_token but never calls it; no expiry/refresh logic (comment admits it). Backend fix required: add a refresh() that POSTs the refresh token on 401, updates unifed_access, and surfaces expiry to the UI toast (§3.6). Until then the session toast is a stop-gap, not a cure.
IA mismatch. Brief assumed /campus /assignments /research /admin as primary tabs; actual tokens.nav = Home/Connect/Create/Discover/Profile. Resolved via drawer (§1, §5.5).
